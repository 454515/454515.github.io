## 1. 项目概述

一款运行于 Windows 平台的本地桌面 OCR 识别工具。核心能力是**身份证信息快速提取**（姓名 / 性别 / 公民身份号码），支持微信拖拽、文件选择、剪贴板粘贴、文件夹导入四种图片输入方式，识别结果一键复制直接适配 Excel 分列。全程本地运算、数据不上传。

**当前版本目标（V1.0）**：身份证识别核心功能 + 四种导入方式 + 批量处理 + 一键复制。

## 2. 技术栈与架构

### 2.1 技术选型

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 界面框架 | PySide6 | 跨平台 Qt 界面，拖拽、表格、进度条 |
| OCR 引擎 | PaddleOCR（PP-OCRv4） | 中文 OCR，本地部署，免费 |
| 图像处理 | OpenCV | 图片预处理、方向校正、透视矫正 |
| 打包工具 | PyInstaller | 打包单 exe，免安装 |

### 2.2 分层架构

```
┌─────────────────────────────────┐
│         界面层（UI）            │  PySide6 界面、拖拽、表格、交互
├─────────────────────────────────┤
│         业务逻辑层              │  识别调度、批量处理、结果管理
├─────────────────────────────────┤
│         OCR引擎层               │  PaddleOCR 通用识别接口
├─────────────────────────────────┤
│         字段提取层              │  身份证处理器、发票处理器（预留）
├─────────────────────────────────┤
│         工具层                  │  图片预处理、剪贴板、格式转换
└─────────────────────────────────┘
```

**核心设计原则**（源自 PRD §4.2）：
- OCR 引擎与业务逻辑解耦，更换引擎不影响上层。
- 字段提取模块化，新增卡证类型只需新增对应处理器。
- 界面与数据分离，便于后续迭代。

## 4. 开发原则

1. **简单优先**：只完成阶段 spec 明确要求的范围，不擅自加功能、不做无必要的抽象。
2. **单文件 ≤ 400 行**：一个 Python 文件超过 400 行时，必须拆分模块。
3. **最小范围修改**：只改与当前阶段直接相关的内容。
4. **代码、命令、日志、变量名一律用英文**；注释与文档可用中文。
5. **每个阶段一个小提交**：一个阶段完成后提交一次，commit message 写清阶段名与改动内容。
6. **不写向后兼容代码**：按当前需求写，不为不存在的未来做兼容。
7. **本地隐私红线**：任何代码路径不得发起网络请求、不得将图片/识别结果上传云端。这是 PRD 的硬性验收项。

## 6. 推进方式（agent.md + skill 协作）

本项目采用 **agent.md 总控 + 每阶段一个 skill 驱动** 的方式推进：

### 6.1 进入一个阶段

1. Agent 或用户以 `/stage-N-<name>` 调用对应 skill，例如 `/stage-3-field-extraction`。
2. 该 skill 加载阶段指令：**先读对应 spec 文件**，再按 spec 实施。
3. 阶段推进期间，agent.md 的第 4、5 节为行为总纲，skill 与 spec 为阶段细纲。

### 6.2 阶段内执行流程（每个阶段都遵守）

```
① 读 spec → 明确本阶段目标、范围、验收标准
② 环境准备 → 确认依赖、上游阶段产物已就绪
③ 实现 → 按 spec 的模块与接口逐个实现，单文件 ≤ 400 行
④ 自测 → 运行 spec 中定义的验证脚本 / 命令，记录结果
⑤ 验收 → 对照 spec「验收标准」逐条核对，未通过则修正
⑥ 提交 → 阶段完成，git commit 一次，message 注明阶段
⑦ 汇报 → 向用户汇报本阶段交付物与验收结果
```

### 6.3 阶段切换规则

- 仅当上一阶段验收标准**全部通过**时才允许进入下一阶段。
- 若在阶段 6 发现阶段 1 的接口有缺陷，回到对应阶段修复，修复后重新走该阶段验收。
- 每次只推进一个阶段，一个阶段完成并汇报后再进入下一个。

### 6.4 遇到歧义

- 需求不明时先向用户（z）说明歧义点，不擅自猜测。
- 有更简单的实现方式时主动提出，但以「满足 spec 验收标准」为前提。

## 7. 全局验收标准（对应 PRD §5.2）

全部 8 个阶段完成后，软件须通过以下 7 项全局验收：

1. 从微信拖拽图片能正常识别。
2. 文件选择、剪贴板粘贴、文件夹导入四种方式均可用。
3. 批量识别 10 张图片，进度条正常显示。
4. 识别结果点击复制后，粘贴到 Excel 自动分成三列。
5. 结果表格支持双击编辑修改。
6. 全程断网状态下软件正常运行（验证本地处理）。
7. 关闭软件后重新打开，无历史数据残留（符合隐私要求）。

另须满足 PRD §3 非功能需求：单张识别 ≤ 1.5s、冷启动 ≤ 3s、内存 ≤ 500MB、Windows 10/11 64 位、JPG/PNG/BMP 格式。
