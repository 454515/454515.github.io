# 阶段 4：UI 主界面框架

## 目标
在 `src/ui/` 下用 PySide6 搭建主窗口的**完整静态布局**，与 PRD §2.2 的界面结构一致：顶部标签页、中央拖拽区域、操作按钮、识别进度条、结果表格、底部操作栏。本阶段只搭「壳」，识别逻辑通过模拟数据接入。

## 前置条件
- 阶段 3 已完成验收。
- 已阅读 [spec-04-UI主界面框架.md](../../../docs/specs/spec-04-UI主界面框架.md) 与 PRD §2.2 界面布局。

## 执行步骤

1. **读 spec**：明确主窗口布局、各控件、结果表格列定义。
2. **搭建主窗口**：按 PRD 的 ASCII 布局实现 `MainWindow`：
   - 顶部 `QTabWidget`：页 1「身份证识别」可用；页 2「发票识别(预留)」置灰禁用。
   - 中央拖拽区（占位组件，本阶段仅静态文字 + 边框）。
   - 操作按钮「选择文件」「粘贴图片」。
   - 进度条（默认隐藏）。
   - 结果表格：列序 = 序号、姓名、性别、身份证号。
   - 底部操作栏：共 N 条结果、「复制全部」「清空」。
3. **接入模拟数据**：写一个临时方法向表格填充演示数据，验证布局与视觉反馈，不接真实识别。
4. **自测**：`python src/app.py` 启动窗口，核对布局与 PRD 图一致。
5. **验收**：对照 spec「验收标准」逐条核对。

## 完成标准
- [ ] 窗口布局与 PRD §2.2 的 ASCII 结构一致。
- [ ] 「发票识别」标签置灰禁用。
- [ ] 表格列序正确，模拟数据可显示。
- [ ] 窗口可正常启动、缩放不布局错乱。
- [ ] 已向用户汇报：主窗口截图（或布局描述）。

## 注意事项
- 本阶段不实现识别、不实现导入、不实现拖拽逻辑（阶段 5/6 的职责）。
- 界面控件一律用英文变量名；界面显示文字用中文（面向用户）。
- 单文件 ≤ 400 行，布局复杂时拆分组件模块。
