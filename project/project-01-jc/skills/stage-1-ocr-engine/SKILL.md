# 阶段 1：OCR 引擎层

## 目标
在 `src/ocr/` 下封装 PaddleOCR，向上层提供**通用的、与具体卡证类型无关**的识别接口。上层（业务逻辑）只依赖本层的接口，不直接接触 PaddleOCR，满足架构解耦原则。

## 前置条件
- 阶段 0 已完成验收（引擎冒烟测试通过）。
- 已阅读 [spec-01-OCR引擎层.md](../../../docs/specs/spec-01-OCR引擎层.md)。

## 执行步骤

1. **读 spec**：明确 `OcrEngine` 类的接口签名、数据模型、线程约束。
2. **实现引擎封装**：按 spec 实现 `OcrEngine`，关键点：
   - 惰性加载：首次识别时才初始化 PaddleOCR，避免拖慢启动。
   - 线程安全：识别过程在线程池中执行，接口需可被 UI 线程安全调用。
   - 结果数据模型：把 PaddleOCR 原始输出转为统一的数据类（文本 + 置信度 + 坐标框）。
3. **实现错误处理**：图片损坏、识别异常返回明确错误码/异常类型，不静默吞掉。
4. **自测**：运行 spec 定义的单元测试，用样例图片验证接口返回结构。
5. **验收**：对照 spec「验收标准」逐条核对。

## 完成标准
- [ ] `OcrEngine` 提供加载 / 识别 / 释放三个明确动作。
- [ ] 识别结果返回统一数据模型，上层不感知 PaddleOCR。
- [ ] 惰性加载生效，`import` 不触发模型加载。
- [ ] 单张识别在普通 CPU 环境 ≤ 1.5s（可实测记录）。
- [ ] 已向用户汇报：接口定义、实测识别耗时。

## 注意事项
- 本层**不做任何身份证业务逻辑**（那是阶段 3 的事），只做「图片 → 文字块列表」。
- 引擎实例全局唯一，避免重复加载模型占用内存。
