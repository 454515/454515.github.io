# 阶段 5：图片导入方式

## 目标
在阶段 4 的主窗口上实现**四种图片导入方式**（PRD §2.1.2 全 P0）：微信拖拽、文件选择、剪贴板粘贴（Ctrl+V）、文件夹导入；外加拖拽反馈（边框高亮、文字变色）。导入的图片进入待识别队列（识别逻辑由阶段 6 接入，本阶段先做「导入 → 加入列表 → 可预览」）。

## 前置条件
- 阶段 4 已完成验收（主窗口可运行）。
- 已阅读 [spec-05-图片导入方式.md](../../../docs/specs/spec-05-图片导入方式.md)。

## 执行步骤

1. **读 spec**：明确四种导入方式的触发链路、图片格式过滤规则、去重策略。
2. **实现拖拽支持**：重写拖拽事件，处理从微信等外部拖入的单张/多张图片，与文件夹拖拽区分。
3. **实现文件选择**：「选择文件」按钮 → `QFileDialog` 多选，过滤 jpg/png/bmp。
4. **实现剪贴板粘贴**：窗口激活时监听 Ctrl+V，读取剪贴板图片 `QClipboard`。
5. **实现文件夹导入**：拖入文件夹时递归扫描 jpg/png 图片。
6. **实现拖拽反馈**：拖入时中央区域边框高亮变色、提示「释放即可识别」；拖出恢复。
7. **自测**：逐一验证四种方式都能把图片加入待识别列表；拖入非图片文件给友好提示不崩溃。
8. **验收**：对照 spec「验收标准」逐条核对。

## 完成标准
- [ ] 四种导入方式全部可用（P0）。
- [ ] 拖拽反馈高亮、提示文字变色生效。
- [ ] 导入非图片/损坏文件时提示友好，不崩溃。
- [ ] 文件夹导入按文件名字母序/导入顺序稳定入队。
- [ ] 已向用户汇报：四种方式自测结果。

## 注意事项
- 微信拖拽的图片来源可能是临时缓存文件，读取后直接进队列即可，勿做持久化。
- 本阶段结束时识别仍可用阶段 4 的模拟数据占位，阶段 6 再接通真实识别。
